# 解决方案实践价值评估 / 分类

目标不是判断项目"好不好"，而是把一个候选项目快速归类到解决方案实践的合适类型，并判断是否值得投入建设。候选项目可能来自开源社区、内部孵化、客户需求或某款产品能力。

## 解决方案实践类型

统一为三类；免费试用是附加标签，不是独立类型。

- **应用方案**：面向完整场景，需要端到端完成部署、文档和测试。
- **Skills**：面向单一明确能力，可被 Agent 或 AI 调用、复用。
- **最佳实践**：重点是将某项产品、技术或方案端到端跑通，并沉淀经过验证的方法、配置和经验。
- **免费试用**（标签）：面向单应用快速体验，需要重构镜像并开发前端体验入口，仅适用于能够独立体验的单应用。可附加到 Skills 和应用方案上；用于 Skills 开发时额外附加 1 人天工作量。

## 预计工作量（人天）

| 类型 | 工作量 |
|---|---:|
| 免费试用 | 约 7.5 人天 |
| 普通应用方案 | 约 15–20 人天 |
| 高可用应用方案 | 约 30 人天 |
| 最佳实践 | 约 5 人天 |
| Skills | 不设固定值，按复杂度判断，通常为 5 人天 |

应用方案按是否高可用区分两类工作量。免费试用是标签：附加到 Skills 时在 Skills 工作量上再加 1 人天；单独面向单应用的免费试用（重构镜像 + 前端入口）约 7.5 人天。

## 商业价值 vs 开发者价值

分别判断商业市场价值和开发者价值，并放入二维矩阵：

| | 开发者价值低 | 开发者价值高 |
|---|---|---|
| 商业价值高 | 企业解决方案 | 核心解决方案实践 |
| 商业价值低 | 低优先级 | Developer Practice |

## 综合判断

先形成场景句："面向【目标客户】，解决【业务问题】，通过【项目核心能力】，实现【业务价值】。"无法形成可信场景时降低建议等级。

工作量是重要参考，但不能只按工作量定类型。最终综合权衡：

1. 场景价值
2. 与解决方案实践类型的匹配度
3. 预计工作量
4. 是否值得投入对应的建设成本

区分事实、推断与未知；资料不足时用现有证据完成评估，明确降低置信度，不把缺信息当正面证据。
