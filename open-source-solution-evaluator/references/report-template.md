# 输出模板

评估结论直接给出以下字段，保持简洁，不堆砌复杂指标。

```text
推荐方案实践类型：应用方案 / Skills / 最佳实践
主推荐类型：XXX        （仅当适合多种类型时）
可衍生类型：XXX        （仅当适合多种类型时）

价值定位：核心解决方案实践 / 企业解决方案 / Developer Practice / 低优先级

是否建议建设：是 / 否

预计工作量（人天）：XX

推荐理由：……
```

字段说明：

- **推荐方案实践类型**：从三类中选一个；如附加免费试用标签，在此一并注明（如「Skills ＋ 免费试用」）。若候选项目适合多种类型，再补「主推荐类型」和「可衍生类型」两行。
- **价值定位**：由「商业价值 vs 开发者价值」矩阵得出，独立于实践类型，说明项目所处的价值象限。
- **是否建议建设**：给出明确结论，并说明判断依据。
- **预计工作量（人天）**：按类型给出人天；免费试用附加到 Skills 时加 1 人天，单独面向单应用的免费试用约 7.5 人天。
- **推荐理由**：概括场景价值、价值定位、类型匹配度、工作量与建设成本之间的权衡。

若「是否建议建设」为否，在推荐理由中说明原因、更低成本的替代交付形式，或重新评估的触发条件。
